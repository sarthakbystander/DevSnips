01 — Features

Built for how teams actually write

A block model, two-way links to your issue tracker, and a command palette—so notes stay structured without getting in the way.

F.01

Two-way issue links

Link a note to a ticket and the ticket links back. Decisions stay attached to the work they decided.

F.02

Offline-first sync

A CRDT keeps every client in sync with no server round-trip for local edits. Works on the train.

F.03

Command palette

Jump to any note, insert any block, or run any action from the keyboard. ⌘K everywhere.

F.04

Runbook blocks

First-class step, checklist, and incident-timeline blocks that render as structured data, not prose.

F.05

Plain-text storage

Notes are Markdown plus a thin block schema. Diffable in git, portable, and never locked in.

F.06

Quiet by default

No badges, no red dots, no noise. Mentions and decisions surface when you ask for them.

02 — How it works

From install to structured notes

  1. 01

    Connect your tracker

    Link GitHub, Linear, or Jira in one step. Linear Field indexes ticket IDs so they resolve inline as you type.

  2. 02

    Write in blocks

    Start with a meeting note, a decision, or a runbook. Each is a typed block with its own structure and shortcuts.

  3. 03

    Link as you go

    Type @ENG-412 and the ticket links back to the note. Decisions and runbooks stay one hop from the code.

  4. 04

    Find it later

    ⌘K into any note, decision, or runbook by title, ticket, or attendee. No folders to maintain.
