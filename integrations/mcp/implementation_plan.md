# DevSnips MCP — Implementation Plan

Status: approved. This file is the executable record of the architecture work. Every claim
below is verified against the working tree at `chore/align-tooling-with-library-spec` @ `60d2f64`.

## Goal

A lightweight, read-only Python MCP server (`devsnips-mcp`) exposing DevSnips to AI coding
agents over stdio. MCP is a consumer of the existing registry — never a second source of truth.

```
AI coding agent → DevSnips MCP → snippets-index.json (registry) → library/<path>/<file>
```

## Verified foundation (from the repository)

- Registry: `snippets-index.json` (version 2.0, tech-first paths with trailing slash,
  on-disk location `library/<path>`); generated by `scripts/tooling/indexing/rebuild_index.py`.
- Specialized indexes (`agents/resources/indexes/*.json`) derive `id` (path minus slash) and
  `install` (`npx devsnips add <id>` when `cli/src/install/downloader.js getSourceFiles()`
  would install). MCP mirrors this predicate and pins it with a parity test.
- The CLI resolves against the remote registry on `main`
  (`https://raw.githubusercontent.com/sarthakbystander/DevSnips/main/snippets-index.json`)
  and downloads files from `library/<path>/<file>`. Verified live: HTTP 200, `ETag` present,
  `Access-Control-Allow-Origin: *`.
- `website/search-index.json` is stale (968 of 1018 variants), uses a different technology
  vocabulary, has no generator in the repo, and `devsnips.dev/search-index.json` + `/llms.txt`
  return 404. MCP does not use it.
- The registry `files` manifest is lossy for React templates (only one level of `src/**`
  listed). MCP reports `files_complete: false` in remote mode and walks the real tree in
  local mode.
- No CI in the repository; Python tooling is stdlib-only; testing convention is plain
  `unittest`-style scripts, no pytest.

## Architecture

- **Transport:** stdio (default of both MCP SDK lines), launched by the client.
- **Read-only:** 4 tools, no write tools, no filesystem writes outside the cache.
- **Providers:** `auto` → local DevSnips checkout if detected, else GitHub raw `ref=main`;
  `http` reserved for a future DevSnips registry/API. Tools never accept URLs.
- **Search:** deterministic, stdlib-only, field-weighted token matching with
  exact/partial/fuzzy modes and full tie-break specification.
- **Errors:** structured JSON payloads with stable codes; provenance block on every response.

## Tools (v1)

1. `search_resources(query?, technology?, type?, category?, family?, tags?, tagsMode?,
   styles?, features?, installableOnly?, limit?, offset?)`
2. `get_resource(id, include?, maxBytes?)` — metadata + README + template AGENTS.md + manifest
3. `get_resource_file(id, file, maxBytes?, truncate?)` — one allowlisted file
4. `list_facets(facet?, technology?, includeVariants?)` — technologies/types/categories/families

## Package layout

```
integrations/mcp/
├── pyproject.toml            # deps: mcp>=1.28 (v2 preferred, v1 adapter included)
├── README.md                 # install + per-client config + tool reference
├── src/devsnips_mcp/         # config, errors, models, index/, registry/, search/, files/, cache/, tools/, server.py
└── tests/                    # stdlib unittest; stdlib-only tests run without the SDK installed
```

## Dependency strategy

- Runtime: the MCP SDK only (`mcp>=1.28`; `pip install mcp` resolves to the current stable
  line). Everything else is stdlib (`urllib`, `json`, `hashlib`, `pathlib`, `difflib`,
  `dataclasses`, `logging`).
- Rejected: httpx/requests (urllib suffices), pydantic (dataclasses), platformdirs (~15 lines),
  diskcache/sqlite (one dir of small files), rapidfuzz (difflib), click/typer (env config),
  pytest (repo convention), any DB/embeddings/web server/Docker.

## Testing

`python -m unittest discover -s tests` from `integrations/mcp/`.

- Unit: models, schema gate, search (determinism snapshots), path/filename resolver, cache
  (TTL, 304 revalidation, atomicity, LRU eviction, corruption recovery), providers (stubbed
  fetcher), contract tests on malformed/future registries.
- Parity: derived ids/installs must agree with the specialized indexes for every variant.
- Integration: in-process MCP client tests + a real stdio subprocess smoke test
  (stdout must contain protocol frames only) — skipped when the SDK is absent.
- Live network tests are opt-in via `DEVSNIPS_MCP_NETWORK_TESTS=1`.

Repository gates after any change: `python scripts/tooling/validators/validate.py`
(`scripts/tooling/indexing/validate_indexes.py` when indexes are involved).

## Phases

0. Contracts & alignment (this document).
1. Python MCP foundation: package skeleton, server, logging to stderr, stdio smoke test,
   verify real clients (Claude Desktop, Cursor, VS Code, Windsurf).
2. Providers + registry loading + cache + `list_facets` + parity test.
3. Search engine + `search_resources`.
4. Retrieval + `get_resource` + `get_resource_file` (+ `files_complete`, `manifest_stale`).
5. Documentation: package README, `agents/resources/mcp.md`, root `AGENTS.md` routing row,
   `docs/mcp/`, CHANGELOG.
6. Truth-up of "no MCP" statements in existing docs (separate commits).
7. Ecosystem integration (PyPI publish, CLI/skill cross-references).
8. Hosted MCP / Registry API (`HttpJsonProvider`, HTTP transport, MCP resources).

## Risks

| Risk | Mitigation |
|---|---|
| SDK/protocol-era client incompatibility over stdio | Prove real clients in Phase 1; thin server adapter keeps the SDK swappable |
| Registry schema drift | Degraded-mode serving + contract tests on future-version fixtures |
| Derived id/install drift from CLI | Parity test vs specialized indexes (required gate) |
| Manifest incompleteness presented as completeness | `files_complete` honesty flag + local-provider full walk + regression test |
| Stale website search index tempting reuse | Explicit "do not use" rule + regression test |
| Windows path/CRLF quirks | Hash decoded JSON, POSIX registry paths, atomic writes, documented client config |
