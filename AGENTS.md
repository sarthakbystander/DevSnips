# DevSnips

An open-source, framework-agnostic frontend component library. UI resources are organized as design-system families across three technologies and three content types. This file is the AI-agent entry point: it tells you what you need immediately and where deeper knowledge lives.

## Purpose

- `library/` holds the canonical collection of copy-paste-ready UI resources — Components (reusable controls), Sections (full website regions), and Templates (complete sites) — in React, Tailwind CSS, and Vanilla HTML/CSS/JS.
- `cli/` installs any resource into a user project (`npx devsnips add <id>`).
- `agents/` is the AI layer: this documentation system, generated machine-readable indexes, and the `devsnips` skill.
- `scripts/` holds all tooling: structure validators, index generators, resource generators, and QA harnesses.

## Source of Truth

1. **Canonical:** the filesystem under `library/` and each resource's `metadata.json`.
2. **Generated — never hand-edit:**
   - `snippets-index.json` — regenerate with `python scripts/tooling/indexing/rebuild_index.py`
   - `agents/resources/indexes/*.json` — regenerate with `python scripts/tooling/indexing/build_resource_indexes.py`
3. **Documentation:** `agents/resources/*.md` (hand-maintained, path-accurate); `website/`, `docs/`, `README.md` are human-facing and may lag.
4. **Counts:** never quote resource counts from any documentation — read `snippets-index.json`.

## Required Agent Behavior

- Inspect the real files before modifying anything; the repository is the source of truth.
- Do not invent files, fields, commands, paths, or counts. If a value isn't derivable from the repo, omit it or verify it first.
- Make minimal changes; never touch unrelated resources or files.
- Generated files (`snippets-index.json`, `agents/resources/indexes/*.json`) are regenerated by scripts — never patch them by hand.
- Do not modify resource implementations just to make tooling easier.
- After changes: run the relevant validator/tests (see QA Expectations) and verify the affected output.
- Failures are information — investigate and report rather than silently working around them.

## Safety / Modification Rules

- Never manually edit generated indexes or preview-shell artifacts derived from metadata.
- Never rename, move, or delete resources without regenerating both indexes and confirming no consumer (CLI resolver, website) breaks.
- New resources must match the exact file contract for their tech + type — see `agents/resources/resources.md` before creating anything.
- Don't change architecture, schemas, or generator behavior without reading `agents/resources/architecture.md` and `agents/resources/indexing.md` first.
- Preserve existing naming, capitalization (`React`, `Tailwind`, `Vanilla`, `Components`, `Sections`, `Templates`), and tech-first index paths (no `library/` prefix) unless the task explicitly changes them.

## QA Expectations

After any change, run the most relevant check — minimum bar:

```
python scripts/tooling/validators/validate.py
```

Regenerate indexes whenever `library/` content or resource metadata changed:

```
python scripts/tooling/indexing/build_resource_indexes.py
python scripts/tooling/indexing/validate_indexes.py
```

What each layer covers, per-framework rules, and QA harness locations: `agents/resources/qa.md`.
